# 交互方式与按钮规范

本文件为设计建议；实际业务权限、幂等、冲突处理和持久化必须由正式任务执行边界校验。

## 一条清楚的主流程

报修人描述问题 → 核对草稿 → 提交为待接单 → 技工接单 → 提出预约 → 报修人确认 → 技工开工和更新进度 → 提交完工说明与证据 → 报修人独立验收。

本次参考页可体验其中的报单、预约和验收，并包含设备身份弹层。接单、开工及过程上传不在本参考包中模拟。

## 关键交互

| 场景 | 进入方式 | 操作与反馈 | 失败或退出 |
|---|---|---|---|
| 预约 | 队列选中任务，详情显示当前阶段 | 大号时间 + 日期 + UTC+8；主按钮打开核对面板，再确认 | 冲突保留原任务且不进入已预约；拒绝须填理由，进入等待新提议 |
| 报单 | 场景标签或“发起报修” | 保留原话；固定候选明确标注；地点、联系人可修改；提交前核对 | 空输入就近报错；未提交始终是草稿；取消核对面板返回原表单 |
| 验收 | 选择待验收示例 | 处理说明、示意附件、维修人与验收人分开展示 | 不通过必须说明理由；回到处理中，正式产品保留原完工版本 |
| 设备身份 | 左侧“设备身份”或建议依据 | 显示编码、安装位置、服务空间和来源 | 本包只有固定设备例子；真实产品须支持无权限、无台账和匹配不唯一 |
| 通知 | 左侧通知 | 轻量面板展示固定通知，点击查看任务 | 不发送真实消息；正式产品需按任务最新版本重新读回 |
| 危险操作 | 组件场景“取消任务” | 说明影响，保留任务为明确退出动作 | 本包只演示确认层，不取消实际任务 |

## 按钮的共同语言

- **主按钮**：当前关键动作，用品牌实色，文案用“确认预约”“确认提交报单”等具体动词。
- **次按钮**：轮廓或浅底，用于查看详情、返回核对。避免与主按钮争夺注意力。
- **文字按钮**：收藏、稍后处理、依据展开等低强调操作；“时间不合适”也必须看得见。
- **危险按钮**：危险语义独立于品牌色，以文字和确认内容说明影响，不只依赖颜色。
- **图标按钮**：只用于高辨识度动作，提供可访问名称；关键提交保留文字。
- **交互状态**：默认、悬停、按下、键盘焦点、禁用、处理中、成功、失败。处理中防重复触发；失败保留输入。
- 常用按钮高度 42px；紧凑小按钮仅用于辅助操作。正式触屏宿主需按实际触控目标复核尺寸。
- 焦点可见，弹层支持关闭与 Esc；状态用文字配颜色。动效只帮助理解变化，尊重减少动态效果设置。

## 视觉差异

| 方向 | 主按钮 | 次操作 | 信息组织 |
|---|---|---|---|
| 青绿 | 10px 圆角、深青绿实心 | 柔和轮廓/文字 | 松弛留白，圆角面板，纵向导航 |
| 钴蓝 | 5px 圆角、钴蓝实心 | 明确边框 | 横向深色导航、数字对齐、工程感 |
| 赭橙 | 3px 圆角、赭橙实心 | 下划线文字与细线 | 暖纸底、衬线标题、右侧任务索引 |
| 石墨 | 7px 圆角、薄荷实心深字 | 暗底轮廓 | 图标导航、面板明度分层、紧凑任务队列 |

## 正式实现时必须接上的部分

1. 按角色和最新任务版本提供可执行动作，不能只靠隐藏按钮控制权限。
2. 成功反馈来自实际服务写入并读回；超时不能直接说“提交失败”，应先查询结果，避免重复单。
3. 预约冲突由服务端核验；时间展示包含日期和时区。
4. 模型只产生建议或草稿，用户核对后才进入任务命令；验收由独立角色操作。
5. 进度展示以真实阶段、更新时间和下一责任人为主；不编造百分比。
6. 示例数据、离线状态、同步中、真实写入失败各自有明确标识；外部接口未连接时不能显示“已同步”。

## 简单体验顺序

先进入青绿版确认一次预约，再重置并体验冲突。切换报单草稿，清空描述检查错误，再填写和提交。切到完工验收，分别体验退回与通过。最后打开按钮页，用鼠标和 Tab 检查各类状态。对其他三版重复视觉比较即可。
