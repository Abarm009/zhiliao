四版使用相同的业务示例与交互，方便比较设计本身。选择建议属于设计判断，尚未经过真实用户研究。

## 可以体验

- 预约：确认前核对完整日期、时区和技工；拒绝理由必填；模拟预约冲突。
- 报单：原话输入 → 固定候选草稿 → 修改地点与联系人 → 确认 → 待接单。
- 验收：查看处理说明和示意附件 → 验收通过，或填写理由退回。
- 按钮：主次操作、文字按钮、危险操作、图标按钮、禁用、焦点、模拟加载和反馈。
- 辅助：设备身份、示例通知、收藏、场景切换、重置演示。

## 文件

- `index.html`：四版总览。
- `01-jade.html` 至 `04-graphite.html`：可点击交互稿。
- `assets/styles.css`：四版视觉参数与响应式布局。
- `assets/app.js`：共享的固定示例及页面内交互。
- 总览使用嵌入页面实时预览，无需截图文件。
- [INTERACTIONS.md](INTERACTIONS.md)：交互逻辑、按钮规范与移交边界。
- [VERIFICATION.md](VERIFICATION.md)：本次实际核验记录。

## 使用边界

这是视觉与交互参考，不是已实现的业务功能，也不是官方宿主接入证明。草稿候选是固定示例，附件为示意图；没有模型调用、身份认证、跨角色协作、持久化、真实预约冲突检测、外部工单接口或真实通知。刷新页面会重置状态，切换风格页面不会继承状态；部分表单字段切换场景后恢复示例值。

报单成功只表示本页进入“待接单”示例。预约确认、技工完工和报修人验收是不同动作，不合并为一个“完成”。本包只选取关键场景展示，接单、开工、过程更新等完整页面仍依正式需求实施。

正式产品继续遵循 [UI 规范](../../docs/implementation/10_UI_UX_SPEC.md) 以及工程架构文档；本包不得用来替换后端契约或权限规则。HTML/CSS 用于参考，选择风格后将布局、色值、组件状态转译到 Makepad / robrix2，并重新验证宿主授权、数据持久化和实际任务执行。

## 怎么修改

1. 整体风格：修改 `assets/styles.css` 中对应 `data-theme` 段；四个入口文件的 `data-theme` 决定风格。
2. 业务文案与交互：修改 `assets/app.js` 对应场景函数及事件处理；保持示例标识和独立验收边界。
3. 改动后重新打开四版，检查预约、报单、验收和窄屏布局；更新截图与核验记录。

Router 已用于辅助复核四版方向及交互边界；未将其表述为主会话模型已切换。
