# 桌面工作台 v2 设计规格

日期：2026-10-08。设计基线：提交 `8d730569546cb57310944bb299695134df773b9d`，原生入口 `app/bundle/main.splash`。本包只新增参考材料，不修改业务实现。尺寸是设计目标，需在真实宿主中测量。

## 1. 当前问题与改法

现有原生候选把身份切换、报修、接单、设备、预约、证据、验收和调试结果集中在一个窄窗。用户同时看到大量与自己当前阶段无关的按钮，任务标题、问题空间、负责人和下一步缺少层级。

新版先让用户选一个任务，再查看同一任务的事实和当前动作。右侧只突出一个主动作，次级动作最多两个；阶段不允许的动作通常隐藏，当前必需但暂不可用的动作禁用并解释原因。调试身份移到设置，不占据每张任务的第一行。

## 2. 页面结构

|区域|1440 × 900 参考|内容与行为|
|---|---|---|
|应用头部|高 76|品牌、当前项目、使用说明、当前身份；不自行绘制第二套系统标题栏|
|工作空间导航|宽 170|我的任务、待我处理、收藏任务；设置在底部|
|任务列表|宽 294|搜索、状态筛选、任务卡；选中项高亮并有左侧标记|
|任务详情|弹性宽度|问题、空间、设备、阶段、预约；概览 / 处理记录 / 附件三个页签|
|详情操作区|宽 282|下一步、当前阶段、协作人、主动作与必要说明|

原型顶部“交互设计原型”与底部“本页交互演示”是评审标记，**不照搬到正式原生应用**。真实应用底部只显示真实连接、同步与缓存情况，不显示虚构在线状态。

1280 × 800：按上述布局实测详情是否仍可读，不强求所有模块同时无滚动。≤1080：导航收为图标，列表保留，操作区移到详情下方。≤760：列表与详情分级显示，提供显式“任务列表”入口。原生版至少验证 1440 × 900、1280 × 800、980 × 760，以及文字放大；保留筛选、选中项和滚动位置。

阶段条为“报修 → 接单 → 预约 → 处理 → 验收 → 完成”。任务精确状态用文字徽标表示，取消单独标记；阶段条不是完成百分比。退回重做返回处理阶段，历史验收轮次与原因保留。

详情内容随当前阶段调整优先级：预约待确认突出完整预约时间；维修中在问题后显示最新处理进度；待验收首先展示本轮维修结果与证据入口。已经完成作用的预约缩为一行摘要，不把当前关键事实推到首屏下面。

## 3. 视觉参数

|用途|色值|
|---|---|
|背景 / 表面 / 次级表面|`#111A1B` / `#1A2628` / `#223638`|
|正文 / 次级文字|`#E2EDEA` / `#A4B8B3`|
|主动作 / 按钮文字|`#91D5BE` / `#132F27`|
|分隔线|`#35494A`|
|注意 / 错误|`#EBCB8B` / `#FFABA0`|

主标题 24–26，分区标题 14–16，正文 13–14，辅助文字 11–12；实际渲染依宿主字体、缩放核对。禁止把原生标题放大到吞掉窗口，也不在可见正文输出事件计数、内核变量或 JSON。

面板圆角 12，按钮圆角 7；主按钮高度至少 44。使用统一细线 SVG / 原生矢量图标，不把表情当作功能图标。键盘焦点可见；状态使用文字、图标和颜色共同表达。禁用控件无需满足普通正文对比度，但其原因说明必须清晰。

## 4. 角色与状态

这是显示策略，不授予权限。真实会话、项目成员资格、技能匹配与 `visible` / `sourceOk` / 任务执行边界仍是判断来源。

|阶段|报修人|承接维修人员|同项目管理员|
|---|---|---|---|
|草稿|修改、提交|不显示他人草稿|按既有权限，不扩大范围|
|待接单|查看等待信息|技能符合时接单|已有分配入口置于管理操作|
|已接单，无设备|查看负责人|确认设备|按既有分配/改派规则|
|已提议预约|确认时间 / 时间不合适|查看等待确认|显示事实，不冒充报修人确认|
|已预约|查看安排|符合时间与现有预约规则后开始维修|按现有规则管理|
|维修中|查看进展|记录进度、补证据；证据通过校验后提交完工|按现有规则管理|
|待验收|查看证据并独立验收 / 退回|等待他人验收，不提供自验|非承接者且合规时有理由代验收 / 退回|
|完成 / 取消|只读历史|只读历史|只读历史|

收藏为当前身份的应用内偏好，不是系统窗口置顶。数量是当前实际加载的可见任务数，分页后不能称全局总量。跨项目身份切换清空不再可见的详情，任何异步回包不能把旧项目数据重新填回来。

## 5. 面板与反馈

预约：显示对象、完整日期/星期、起止时间、时区、维修人；确认后提交真实命令，待回读后才显示“已预约”。调整时间需原因；旧提议保留历史。

进度：文字输入先保留，失败可重试。附件区有选择、上传中、校验中、就绪、失败、隔离等实际状态；缺少真实链路就显示不可用。文件名、字节数和哈希不得伪造；附件删除与隔离沿用既有规则。

验收：先查看真实维修结果与证据，确认现场和证据后提交。管理员代验收明确理由；承接者不能验收或退回自己的完工。退回需原因，显示第几轮，原证据和旧完工记录保留。

提交：按钮立即禁用并显示“提交中”；响应丢失使用原幂等键核对。状态冲突回读最新任务，保留输入，不再次创建。失败说明与表单同屏，不只在底部闪一下。

加载、空列表、搜索无结果、无权限、断线、模型不可用各有独立说明。真实 AI 建议只在真实结果到达时出现，包含可核对依据；模型未接通允许人工继续，不播放预写推理和假工具进度。

新建草稿与原因面板关闭时提示未保存内容，Esc 同样遵守；无修改可直接关闭。表单错误聚焦首个错误字段并保留其他字段。页签要支持键盘与清晰选中态；原型基本交互通过后，原生实施仍需补完整焦点和读屏验证。

## 6. 原生落地映射

|设计入口|现有函数/边界|本轮范围|
|---|---|---|
|新建 / 提交草稿|`createDraft` / `confirmDraft`|用表单替代固定示例文字；保留校验|
|接单 / 管理分配|`acceptTask` / `assignTask` / `reassign`|按身份状态显示，不改变资格规则|
|确认设备|`bindAsset` / `unbindAsset`|设备与问题空间分别展示|
|预约面板|`proposeAppointment` / `confirmAppointment` / `rejectAppointment`|将真实字段接到输入；沿用时间/冲突校验|
|处理与证据|`startProgress` / `recordProgress` / `addEvidence` / `quarantineEvidence`|不可用链路诚实禁用，不能伪造 ready|
|完工 / 验收|`submitCompletion` / `acceptCompletion` / `rejectCompletion`|保留执行边界、证据门槛、轮次与禁止自验|
|其他操作|`cancelTask` / `togglePin`|按权限收纳；终态只读|

目前部分函数把原因、记录内容写死。接入用户输入时需明确更新参数与调用方，继续经过原执行边界，补边界验证；不是只把文本框画上。不能改旧 `backend/src/wagent_backend/ops/contracts` 迁移契约，也不能为界面另造任意状态转换。

原型文件是 HTML/CSS/JS 参考。正式比赛包仍按官方脚本原生路线实现，不另做桌面壳、不把本机 Python 服务塞进 bundle。宿主曾有 ScrollYView 子控件实例化问题，先用当前宿主支持的容器做最小可运行布局，再检查滚动与视口外按钮。

## 7. 建议实施顺序

1. P0：任务列表、选中详情、一个主动作、角色过滤、石墨尺寸层级、原始状态与业务事实回读。
2. P0：预约表单、进度表单、验收/退回原因、错误与禁用原因、终态只读；真实宿主可点击可滚动。
3. P1：搜索、待我处理、收藏、响应式布局与焦点保留；依真实可见数据计算数量。
4. P1：已有 AI 能力的展开依据与状态显示；真实链路未接通不新增承诺。

若宿主无法支持完整宽屏布局，先交付“列表 + 详情、详情内固定行动区”的两区版本，记录差异。不要为了达到截图外形删除业务校验或降掉原 P0 / 38 项业务 / 12 项 UI 验收。
