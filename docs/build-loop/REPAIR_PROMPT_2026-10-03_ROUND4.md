## 三、问题、修改要求与验收标准

### R3-01｜草稿编辑绕过命令边界，500 后仍写入（P1，最先修）

**问题：** `api/__init__.py` 的 update_draft 直接使用自动提交连接；原请求重试 409，同键换内容返回 500，但联系人、版本和事件已改变，成功回执未对应更新。

**修改要求：** 将 update_draft 收敛为领域命令，路由只负责输入与响应适配。当前授权、幂等检查、版本检查、更新、业务事件和成功回执必须在正确的事务边界内完成；统一使用应用时钟。修正与 SQLite 实际行为不符的注释。不能只捕获重复键异常、改 HTTP 状态码或增加空的 `with conn`。

**验收：**

- 首次合法编辑返回 200，恰好一次业务更新、一条对应编辑事件、一条成功回执；版本只加一次，时间来自注入时钟。
- 完全相同请求重试返回成功，保留原 action_id 和业务结果，任务/事件/成功回执不再增加；允许按契约附加回放标志。不能因为原 expected_version 已旧就拒绝合法回放。
- 同主体同 key 换命令、内容或 expected_version，按契约返回 409，所有业务数据和成功回执不变。
- 在写事件、写成功回执等阶段注入失败，整个业务事务回滚，不能留下“任务更新成功但没有回执”；独立失败审计可以追加。
- 两个不同请求以相同旧版本并发编辑，只有一个成功，另一个版本冲突，不丢失更新、不产生与任务版本不一致的事件。
- 撤权、非本人、非 DRAFT、跨项目空间均拒绝；修改草稿空间时重新验证或明确处理已有设备的服务关系，不制造不一致的草稿。已有数据及旧契约保持兼容。

列出当前全部业务写入口及其最终执行边界，覆盖 API、领域方法、工具/旧 runner 和原生适配；对暂不适用的入口说明理由。确有独立执行实现的原生路径需独立证明等价守卫，不能用 Python 测试替它验收。

**验收：**

- 保留 B 项目有效身份、移除 A 项目后，A 的全部相关首次写操作、新 key 重试与旧 key 回放均按契约拒绝；原有合法读写 B 的能力保留。

- 分别覆盖项目成员撤销、所需操作角色撤销、承接者变化、多角色主体；不泄露无权对象的回执内容。
