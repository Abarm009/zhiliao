## 5. 测试层次和数据

原生UI另按[10 UI与交互规范](10_UI_UX_SPEC.md)执行U01–U12，包括视觉一致性、窄窗/文字放大、键盘、真实动作反馈及异常恢复。38项业务用例与12项UI用例分别记录，不以静态设计稿替代原生可用性。

- 规则单元测试：显式注入服务端时钟，覆盖状态表每个允许/拒绝边；不依赖真实模型。
- 数据集成测试：临时SQLite文件，多独立连接/线程制造真正竞争；不能两个请求串行执行后称并发通过。
- API集成测试：真实会话与项目授权、幂等、文件、错误信封；注入假模型仅验证应用契约。
- 原生宿主测试：官方固定版本真实控件、权限确认、任务结果回读；记录宿主SHA、app.card摘要、截图/操作证据。
- 模型测试：真实服务、同一场景多个自然表达、记录provider/model及工具来源；与离线测试分开报告。
- 比赛数据：至少两个项目、两个报修人、两个技能不同技工和一经理、含安装/服务空间不同的设备、重叠预约场景。均为明确合成数据，避免迁移私有真实资料。

判定任务成功看数据库状态、动作回执、证据与用户验收。页面出现绿色提示、HTTP200、模型结束均不能单独证明完成。
