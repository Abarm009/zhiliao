## 2. 原生宿主方案：先证明最小桥接

主路线：从赛事链接的原生文章编辑器示例理解固定app_id/version/digest、账号授权与原生控件；新增固定的维修应用标识 `local.repair.assistant`（本项目拟定，不是官方ID），实现受控能力broker和原生页面。

G0 最小切片必须完成：构建选定宿主 → 打开维修应用 → 用户明确授权 → 读取一项本地测试任务 → 提交一个授权动作 → 回读新版本 → 关闭/重开 → 旧授权失效且重新授权后读回同一任务。

**不能照抄文章编辑器就认为已有后端身份方案。** 官方示例自己说明没有独立远端后端；本产品新增 Python 服务，所以必须实现下述会话绑定。本轮仅验证同一台机器的 loopback连接；远端身份/生产认证另做。

### 本地会话绑定与权限分工（自有设计）

1. 原生 broker 向 Python 后端发起配对，取得120秒有效的用户码和轮询秘密；秘密仅保存在 broker，后端只保存哈希，不写入普通日志。
2. 用户在已登录的本地Web管理页核对实例和用户码并审批；后端绑定当前Web用户，不接受任意user_id，不把宿主自报的账号字符串视为认证证明。
3. broker持轮询秘密领取一次性后端会话，重复领取拒绝；G0执行过期、错误秘密和重复消费测试。单纯 `X-User-Id` 或请求体 `role=MANAGER` 一律不可作为权限凭据。若官方提供可验证身份票据，优先用官方机制替换本地配对。
4. 宿主获授后的后端会话只保存在受控 Rust broker 内，应用脚本不拿到Matrix token、后端token或配对秘密。应用每次调用需附匹配的实例grant，宿主校验后再发送后端请求。
5. 后端独立检查会话、项目权限、请求动作、版本和幂等。宿主确认是额外的人机授权，不能替代后端业务鉴权。
6. 关闭应用、退出账号、登录代次变化或到期时撤销grant和后端会话。撤销失败先在宿主本地停止使用，后端会话短期到期；已发出的动作通过同幂等键查询结果，不能显示“已撤销业务”。

为避免给编码模型一个含糊的“自己设计认证”，本地配对协议和端点列在 [数据与API](04_DATA_API.md)。它只保证演示环境的受控配对，不声明生产远端信任已实现。

### 原生能力面

固定允许的能力：读取当前会话信息、查询本项目设备、查询本人可见任务、获取任务投影、提交声明过的命令、上传当前任务证据、读取站内通知。UI回调映射到命令枚举，不开放任意URL、任意工具名或任意文件路径。

原生控件负责真实点击、输入、候选选择和反馈；Octoscript L0用于已声明结构及绑定，不能假定它可以执行任意网络请求。网络调用和权限留在宿主Rust层。先按本包数据协议实现视图模型，再对照官方固定版本接入具体控件API。

## 3. Web回归入口

新路由 `/repair/`，构建产物独立目录。通过同源HttpOnly会话cookie登录；写请求校验CSRF token和Origin；不把角色保存在localStorage后当作后端身份。

Web端使用与原生相同的任务/动作协议和角色投影。原生UI和Web UI不共享前端框架，只共享生成的DTO和业务接口。不为了同时渲染两个端而发明一个通用UI DSL。

## 4. 后端部署与运行模式

- 新增显式 `WAGENT_MODE=contest`：只挂载新应用、健康及必要只读回归能力；旧ops写路由、写MCP、图谱写入、reset默认禁用。
- `WAGENT_MODE=legacy_dev` 仅用于旧基线本机测试，不能当比赛运行模式，也不能与contest共用写数据库。
- 默认监听127.0.0.1:8711；新库为runtime/repair.db，旧演示ops.db仅用于隔离回归。宿主、后端在同一桌面机器，不要求另做桌面壳。
- SQLite启用foreign_keys，连接短生命周期；WAL及busy_timeout通过初始化明确配置。业务事务不得跨await或模型请求。
- 附件存runtime/attachments/，服务端随机文件名；下载检查任务权限，不直接把目录静态公开。清理未引用附件有持久化作业或维护命令。
- 模型key放backend/.env或部署环境；宿主不嵌入模型key。开发协作使用Codex Router；产品使用可配置兼容模型端点，Router若作为运行端点必须另行验证，不把开发会话当产品服务。
- 禁止将历史演示as_of参数开放给真实业务时钟；演示数据日期与当前预约时钟分离。

## 6. 本轮不采用

不新增微服务、Redis/Celery、Kafka、Kubernetes、独立桌面壳、全量Rust后端改写、向量数据库或通用多Agent流程平台。若宿主必须改Rust，只修改接入/界面和受控broker，Python继续承担领域业务。

性能先测任务响应、预约确认等待、SSE恢复、数据库写锁等待和每任务模型成本，不凭空承诺并发数或延迟指标。SQLite或单进程确实成为瓶颈后才提交技术变更。
