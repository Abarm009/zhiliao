## 已确认范围

用户要求本项目实现报单、接单、设备身份、桌面展示、预约时间、进度等功能，并以官方赛事为交付约束。外部工单系统本轮只预留写入接口。长期仍面向现有业务系统的 AI 协作层。

- 比赛阶段：本系统是本地维修任务的事实源。它确实保存、接单、预约、推进、验收，不是假页面。
- 外部工单：`external_sync_state=NOT_CONFIGURED` 为默认；绝不生成假外部工单号或假成功回执。本地任务号与外部单号分开显示。
- 将来：新接入项目按明确的 `authority_mode` 迁移；本轮仅实现 `LOCAL`，`EXTERNAL` 只为后续保留，配置为后者必须拒绝启动，不能暗中双写。
- P0 桌面交付：在官方 robrix2 桌面宿主中运行并读取同一任务的维修小程序/卡片；普通浏览器只用于开发回归。操作系统桌面置顶小组件、手机、完整 OctoSense Shell 卡片搬移属于单独待验证能力，不冒充已经接通。
- 设备身份：项目内稳定设备 ID、台账、位置/服务空间关系、二维码/编码解析、人工确认绑定及来源。二维码只是定位入口，不是访问授权或硬件证书；P0 支持粘贴/输入二维码载荷，摄像头扫码为 P1。

## 角色

- `REPORTER`：创建自己的任务、提交报单、确认/拒绝预约、查看自己的进度、验收或退回。
- `TECHNICIAN`：查看其项目和技能范围的待接单；原子接单后绑定设备、提议预约、开工、记录进度、提交完工。
- `MANAGER`：查看所辖项目，分配/改派、异常处理、设备绑定更正、取消；代验收必须填写理由并记录代验收身份。
- `SYSTEM`：仅执行已编码的提醒/到期动作，不能作为通用超级用户登录或被模型指定。

## 统一命名

- 任务状态：`DRAFT → OPEN → ACCEPTED → SCHEDULED → IN_PROGRESS → AWAITING_ACCEPTANCE → COMPLETED`；终止分支 `CANCELLED`。
- 预约状态：`PROPOSED / CONFIRMED / REJECTED / EXPIRED / SUPERSEDED / CANCELLED`。
- 外部同步状态：`NOT_CONFIGURED / PENDING / SUCCEEDED / FAILED / UNKNOWN`，与任务状态独立。
- 动作状态：`SUCCEEDED / REJECTED / FAILED`；本地动作同步事务完成，外部同步未知只属于 outbox/external_sync，不让本地事务悬空。
- 接单：技工自主 `accept_task`；经理指定 `assign_task` 会将任务置为 ACCEPTED，事件明确“经理分配”，不伪称技工已确认。
- 预约：接单后由当前技工/经理提议，报修人确认。提议不锁定资源，确认时在事务内检查同一技工时段冲突。
- 完工不是验收：技工提交处置记录后进入 AWAITING_ACCEPTANCE，报修人或有理由的经理验收后才 COMPLETED；退回进入 IN_PROGRESS。

## 部署与实现原则

Python/FastAPI 模块化单体；沿用锁文件；SQLite 单库保存新 `repair_*` 表；数据、会话、附件放 runtime/。新协议在 `task_contracts/`，任务执行在 `application/`。本轮不重写旧 ops/contracts、不新造桌面壳、不拆微服务。

比赛主 UI 采用 robrix2 宿主扩展：Rust + Makepad + 固定 Octoscript L0 界面定义；宿主管理权限，受控桥接访问 Python 后端。Web 回归 UI 才采用 TypeScript + Vite + 原生 DOM/CSS，构建后由 FastAPI 同源提供。具体宿主改法须经过官方版本的接入门；HTTP/SSE 是本系统协议，不宣称是官方 API。

所有本地业务写入（UI、新旧 runner、旧路由、MCP、调度）必须经过共同命令执行器。只读查询不创建任务。旧写入口接入完成前在比赛运行模式禁用。

AI 必須实接模型进行结构化抽取、设备/历史检索、建议及阶段摘要；事实来自工具与数据库。模型不能直接指定可信身份、写任意 SQL、伪造进度、单方面确认预约或验收。人工表单可在模型失败时继续，不将其计为真实模型测试成功。

## 本轮默认产品取舍

这些是设计选择，不是官方规则：单组织、多个项目的演示数据；一任务 P0 最多绑定一台主设备；本地角色账号用于演示，非生产认证承诺；预约采用明确起止区间；无自由百分比进度；不实现支付、备件采购、IoT 控制、完整排班或自学习效果。

官方规则、宿主版本与未验证事项以 [06_OFFICIAL_COMPLIANCE.md](06_OFFICIAL_COMPLIANCE.md) 为准；接口和字段以 [04_DATA_API.md](04_DATA_API.md) 与机器可读契约为准。编程模型不得把设计中的目标模块描述为现有实现。
