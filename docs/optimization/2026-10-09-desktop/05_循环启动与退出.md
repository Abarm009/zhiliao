## 1. 发动机：驱动脚本 run.py

- **路径**：`runtime/optimization/2026-10-09/driver/run.py`
- **做什么**：按 M0 → M7 的顺序串行推进，同一时间只跑一个模块。每一轮依次是：
  1. **MiniMax 构建**：`claude -p`，用 CC Switch 当前的供应商「MiniMax m3」。只有它写代码。构建前会确认当前供应商是 MiniMax，不是就停。
  2. **Kimi 审查**：`kimi -p`。只给极尽详细的修改建议，不写代码；下一轮 MiniMax 必须逐条照做。
  3. **gpt-6.1-sol 终检**：`codex exec -m gpt-6.1-sol`。只有 Kimi 判 PASS 后才做终检，终检通过才进入下一个模块。
  - Codex 不参与构建。2026-10-09 22:30 以前的旧版本是 Codex 建、Claude Code 审，那一版已经废弃，备份为 `run.py.bak-codexbuild`。
- **状态**：记在 `docs/optimization/2026-10-09-desktop/GATES.json`，每个模块有一个 status：NOT_STARTED、READY_FOR_REVIEW、PASS、FAIL、BLOCKED 或 NOT_RUN。
- **日志**：
  - 总日志：`runtime/optimization/2026-10-09/driver/driver.log`，每一步都会追加一行带时间的记录。
  - 每轮的输出：`driver/M<模块>_r<轮次>_<启动时刻>_build.log`、`_review.log`、`_finalcheck.log`、`_sol.log`（gpt-6.1-sol 介入）。例如 `M0_r1_2256_build.log`。
  - 证据和报告：`runtime/optimization/2026-10-09/M<模块>/r<N>/` 和 `docs/optimization/2026-10-09-desktop/reports/`。

### 怎么启动

进程必须完全脱离当前终端会话。只用 `nohup … &` 的话，会话一结束进程就会被带走，22:39 就是这样失败的。在 driver 目录下执行：

```bash
cd "/Users/abeam/一些尝试/知了OctoSense/runtime/optimization/2026-10-09/driver"
python3 -c "
import os,subprocess
if os.fork()==0:
    os.setsid()
    if os.fork()==0:
        f=open('nohup.out','a'); subprocess.Popen(['python3','run.py'],stdout=f,stderr=f,stdin=subprocess.DEVNULL,start_new_session=True)
    os._exit(0)
"
```

- 只跑某几个模块：在 `run.py` 后面加模块号，例如 `['python3','run.py','M1']`。
- 已经 PASS 的模块会被自动跳过。
- 启动由知了执行；Abram 在聊天里说「跑」就行。

### 怎么看进度

- `tail -n 20 driver/driver.log`：看最近几步。
- `ps -axo pid,ppid,etime,command | grep -E "run.py|claude -p|kimi -p|codex exec" | grep -v grep`：看进程还在不在。正常情况下 run.py 的父进程是 1。
- 看 `GATES.json` 里各模块的 status，以及 `reports/` 里最新的报告。
- 最简单的办法：直接在聊天里问知了。

### 什么情况下它会自己停（driver.log 里会出现 `STOP:`）

1. **需要 Abram 授权**：构建或审查认定剩下的阻塞必须 Abram 拍板，也就是在日志里写了 `NEEDS_ABRAM=yes`。这三件事是：AppHub publish（要联网、签名、上架）、配置真实模型 provider、确定业务身份来源。
2. **改不好**：某个模块连续 3 轮没过 → gpt-6.1-sol 介入，写出修改方案 → MiniMax 照着再改一轮 → 还是没过，就停下来等 Abram。
3. **工具一启动就报错**：任何一步不到 2 分钟就以非零码退出，说明工具本身有问题，直接停，不算作一轮。
4. **供应商不对**：CC Switch 当前的 claude 供应商不是 MiniMax 时，不构建，直接停。
5. **全部完成**：M0 到 M7 都 PASS，日志写 `ALL DONE`。

> 说明：BLOCKED 或 NOT_RUN 本身不会让循环立即停下。旧版本是一遇到就停；新版本会继续修，直到上面第 1 条或第 2 条成立。

## 2. 哨兵：知了的巡检

- **频率**：每小时的 :12、:32、:52 只读检查一次。
- **看什么**：driver.log、相关进程、日志和会话文件最近的写入时间、GATES.json、reports/ 里的新报告。巡检不改任何文件。
- **什么时候叫 Abram**：只有出现以下情况，才在 Grok Bot 里知了的聊天中发消息：换模块或换轮次、出了新报告、gpt-6.1-sol 终检或介入、循环 STOP（附原因）、模型或工具报错、超过 30 分钟没有新的写入（疑似卡住）。没有变化就不发消息。
- **介入**：看到 MiniMax 明显做坏了，比如改了本项目文件夹以外的东西、伪造证据、删了别人的改动，知了可以停掉当前构建、打回重做，并在聊天里说明。
- **自动删除**：循环结束（ALL DONE，或者 STOP 后已经汇报并交给 Abram），或者到 2026-10-12 之后，巡检会删掉自己。
- **怎么确认巡检在跑**：巡检是保存在知了那边的定时任务，不在这台 Mac 上，所以 Mac 上查不到它的进程。可以在 Grok Bot 里知了的侧栏查看定时任务（Routines），也可以直接在聊天里问知了。
- **怎么删掉**：在聊天里告诉知了「删掉巡检」或「暂停巡检」。

## 3. 两者的关系

- **run.py 是发动机**：在 Abram 的 Mac 上自己跑，按规则构建、审查、终检，遇到上面列的情况就自己停。
- **巡检是哨兵**：不开车，只盯着。它负责发现卡住、出错、跑偏，或者需要 Abram 拍板的情况，然后在聊天里报告；必要时由知了出面介入或重启。
- 发动机停了，哨兵会报告原因；哨兵不会在 Abram 不知情的情况下替他做那三件需要授权的事。

- 有问题就在 Grok Bot 里找知了；知了是唯一的对接人，Abram 不需要直接去找 MiniMax、Kimi 或 Codex。
