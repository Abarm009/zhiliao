# 桌面应用优化与逐模块 Review 指令包

日期：2026-10-09（Asia/Shanghai）。状态：**方案与指令已编写；全部模块尚未执行或验收。**
本轮只新增方案文档及入口，不修改应用源码、不执行模型/业务测试、不发布。
方案置信度：模块职责和验收组织高；宿主能力与最终运行路线待 M0 实测。

## 先读与使用

1. 读 [整体架构](01_整体架构.md)，确认桌面产品、业务规则和证据边界。
2. 读 [Review 与交接规则](02_Review与交接规则.md)。编码自测不能给自己最终放行。
3. 从 M0 开始，把对应文件中“修改指令”的完整代码块交给构建会话。
4. 构建会话提交候选快照、实现报告和运行证据后，把同文件“Review 指令”的完整代码块发回审查会话。无需把大量日志粘进聊天；可访问的本地路径或固定提交即可。
5. Review PASS 才进入下一模块；FAIL 原模块修复再审；BLOCKED 先解决能力/环境/授权依赖；NOT_RUN 不放行。
6. 本包中的指令是待用户逐次发出的工作范围，不授权本次文档编写自动执行未来模块。

## 模块入口

|模块|结果|指令与验收|
|---|---|---|
|M0 桌面运行基线与能力裁决|确认这份桌面应用准备在哪个宿主版本运行，以及模型、文件、身份和存储是否有可实施路径。|[修改 + Review](M0_桌面运行基线与能力裁决.md)|
|M1 原生桌面框架与交互基线|交付真正可操作、层级清楚的桌面工作台，让后续业务都在同一个界面上增长。|[修改 + Review](M1_原生桌面框架与交互基线.md)|
|M2 可信身份与可靠任务执行|一次用户操作只能被正确执行一次，结果未知可对账，失败和重启不会制造假成功。|[修改 + Review](M2_可信身份与可靠任务执行.md)|
|M3 真实输入与AI报修|从用户实际描述得到可编辑、有来源的报修草稿，经人确认后创建可回读工单。|[修改 + Review](M3_真实输入与AI报修.md)|
|M4 接单设备与预约桌面流程|把既有业务规则接成桌面上可理解、可填写、可确认的一段真实处理流程。|[修改 + Review](M4_接单设备与预约桌面流程.md)|
|M5 真实附件完工与独立验收|让真实证据支持完工，并由独立可信主体完成验收或退回重做。|[修改 + Review](M5_真实附件完工与独立验收.md)|
|M6 桌面体验收口与持续跟进|让桌面应用能持续使用，并补齐既有 P0 中尚未覆盖的跟进与 AI 场景。|[修改 + Review](M6_桌面体验收口与持续跟进.md)|
|M7 同版本总验收与发布准备|拿出可复现、材料一致的桌面发布候选；明确本地验收、发布、赛事提交和收录的不同状态。|[修改 + Review](M7_同版本总验收与发布准备.md)|

M0 → M1 → M2 → M3 → M4 → M5 → M6 → M7。每次只处理当前模块，保持用户要求的串行放行；不自动进入下一模块，不自派并行代理。
桌面 UI 在 M1 奠基、M3–M5 随业务交付、M6 收口、M7 最终复验，不是最后才画的皮肤。
