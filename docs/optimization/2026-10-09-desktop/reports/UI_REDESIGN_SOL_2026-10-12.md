### 2.3 必须避开的实现陷阱

**普通 `View` 不会因为设置颜色就自动绘制背景。**

`W/view.rs:79` 的 `show_bg` 默认是 `false`；`:1231` 只有开启背景绘制才调用 `draw_bg`。当前这些位置需要重点调整：

- 顶栏、侧栏、列表头：`M:10547`、`:10608`、`:10680`。
- 详情卡：`M:10753`。
- 六段阶段条：`M:10728`。

对应修改原则：

| 用途 | 使用组件 |
|---|---|
| 只负责排列 | `View` |
| 纯色面板、分隔线 | `SolidView` |
| 有圆角和边框的卡片 | `RoundedView` |

有背景的容器同时核查 `new_batch: true`，避免背景与文字绘制顺序问题；相关本地说明见 `runtime/native-build/makepad/splash.md:65`。

**本轮不依赖以下能力：**

- `ui.<控件>.set_enabled()`：本地 `Button` 的 Rust 方法存在，但脚本调用分发没有对应分支。见 `W/button.rs:542`、`:855`。
- 动态 `set_visible()`：当前项目记录固定宿主曾失败；较新本地源码中的实现不能覆盖该实测边界。见 `M:10745`、`:11665`。
- 动态修改任意 `draw_bg` 属性、动态追加子节点。
- CSS Grid、媒体查询、`position: sticky`、CSS 阴影。
- 未验证的图标字体、资源路径和自动响应式断点。

## 4. 整体视觉方向

采用“**清晰的石墨维修工作台**”：

- 深色背景，面板只通过轻微明度差和细边框分区。
- 薄荷色集中用于当前主要动作，减少大面积青绿色块。
- 左侧快速切换任务范围，中间选择任务，右侧读详情和执行操作。
- 文字优先，首轮不增加装饰插画、阴影或新图标。
- 所有控件有统一尺寸，取消默认外边距带来的随机留白。
- 每个任务只突出一个当前主动作，继续由现有 `mainAction()` 决定。

配色沿用已冻结的石墨设计，依据 [15_BUILD_VERIFY_LOOP.md](/Users/abeam/一些尝试/知了OctoSense/docs/implementation/15_BUILD_VERIFY_LOOP.md:37)，不另换主题。

## 8. 1280×616 矮屏适配

### 8.1 根因

右侧 `M:10721` 是 `height: Fill`，但详情和整个行动表单连续使用 `height: Fit`。累计内容远大于可用高度，右侧没有对应滚动容器。

侧栏同样放入导航、筛选、提醒、恢复、AI 和手工输入，并包含两个 `height: Fill` 空白填充，见 `M:10615`、`:10620`。矮屏下，底部功能难以到达。

### 8.2 布局方案

采用**三个互相独立的滚动区域**：

- 侧栏：导航、筛选、提醒、恢复和辅助操作滚动。
- 列表：列表头和分页固定，任务行滚动。
- 详情：任务标题、页签和当前动作固定，表单及详情滚动。

固定底部采用正常的 `flow: Down` 子节点排布，不使用覆盖式浮层。

以**应用内容区**确实为 1280×616 为设计预算：

| 区域 | 高度 |
|---|---:|
| 顶栏 | 56 |
| 登录与身份区域 | 88 |
| 全局反馈 | 28 |
| 剩余工作区 | **444** |
| 右侧任务标题 | 64 |
| 右侧页签 | 36 |
| 右侧固定操作区 | 96 |
| 右侧内容滚动视口 | **248** |

列宽首轮采用：

```text
侧栏 144 + 列表 280 + 分隔线 2 + 详情 Fill
```

这不依赖运行时断点判断，也给截图中较窄的应用子窗口留出详情空间。

**实施要求：**

1. 根和工作区使用 `Fill`。
2. 滚动视口处于明确有高度的工作区中。
3. 滚动内层使用 `height: Fit`。
4. 内部字段、按钮使用固定高度或 Fit，避免 Fill 空白填充。
5. 表单最后一项之后保留 24 的底部内边距。
6. 全局反馈超过单行时，完整原因仍在对应滚动内容中可读。
7. 不通过缩小全部字号解决遮挡。

### 8.3 固定宿主的滚动风险

`M:4` 记录过旧宿主对被裁剪控件实例化的限制。因此实施前必须验证：

- 初始屏外的 TextInput 能否滚动到达、输入和读取。
- 初始屏外的按钮能否点击。
- `refreshDesktop()` 和 tick 能否访问这些命名控件。
- 滚动到最底部后，错误及末尾操作是否完整可见。

**如果该探针失败，本批应标记 BLOCKED。** 不能删除功能、缩小成不可读小字，或宣称只加 ScrollYView 就解决了遮挡；宿主兼容性修复需另立范围。

同时分别测试宿主窗口和应用子窗口尺寸。现有启动脚本使用 `1280x800`，见 `demo-20261012/launch_demo.py:145`；这不等于应用内部有同样的可用尺寸。
